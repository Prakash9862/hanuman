# Hanuman OS — Vision de l'interface

## Objectif

L'interface de Hanuman n'est pas un simple tableau de bord.

Elle constitue le poste de pilotage d'un système d'orchestration personnel capable de connecter des outils spécialisés, d'exécuter des flux, de surveiller son propre fonctionnement et, à terme, de coordonner des agents IA.

L'objectif est qu'un utilisateur puisse comprendre en quelques secondes l'état global de son système.

---

# Philosophie

L'interface ne montre pas uniquement des informations.

Elle raconte ce que fait Hanuman.

Chaque élément visible doit avoir une signification.

Une animation ne doit jamais être décorative.

Elle doit représenter une activité réelle du système.

---

# La constellation

La constellation est l'écran principal de Hanuman.

Elle représente l'univers des connecteurs.

Hanuman est situé au centre.

Autour gravitent les différents systèmes externes :

- Notion
- Obsidian
- GitHub
- Gmail
- Calendar
- Google Maps
- Wikipedia
- Gallica
- IMSLP
- Chess.com
- Stockfish
- OpenAI
- ...

La constellation n'est pas une vue des flux.

Elle représente les systèmes auxquels Hanuman est connecté.

---

# Les planètes

Chaque connecteur est représenté par une planète.

À terme, les planètes ne devraient plus utiliser d'icônes.

Chaque planète possédera sa propre identité :

- taille
- couleur
- texture
- halo
- animation

L'objectif est qu'un utilisateur identifie immédiatement un connecteur sans avoir besoin de lire son nom.

---

# Les liens

Les liens représentent les relations possibles entre connecteurs.

À l'état de repos, ils restent très discrets.

Lorsqu'un connecteur est sélectionné, seuls les flux utilisant ce connecteur deviennent visibles.

Exemple :

GitHub

↓

GitHub → Notion

↓

Pull Request Review

↓

Daily Report

Le but est de comprendre instantanément :

- quels flux utilisent ce connecteur ;
- dans quel sens circulent les données ;
- quels flux sont actifs.

---

# Les flux

Les flux ne sont pas représentés comme des planètes.

Ils constituent les capacités de Hanuman.

Ils sont accessibles depuis la section "Flux" de l'interface.

Exemples :

- Obsidian → Notion
- Wikipedia → Notion
- GitHub → Notion
- Calendar → Maps → Gmail
- Chess.com → Stockfish → Obsidian → SCID

Chaque flux dispose de sa propre page.

---

# Sidebar

La navigation principale est organisée autour des concepts du projet.

- Accueil
- Flux
- Connecteurs
- Données
- Santé
- Agents IA
- Paramètres

La barre latérale doit rester compacte, lisible et évolutive.

Les espaces libres pourront progressivement accueillir :

- compteurs
- activité récente
- statistiques
- état du moteur

sans devenir un tableau de bord surchargé.

---

# Santé

La santé est une couche transversale.

Elle surveille :

- les connecteurs ;
- les flux ;
- les exécutions ;
- les erreurs ;
- les performances ;
- les files d'attente ;
- les journaux d'exécution.

Elle permet de comprendre rapidement si le système fonctionne correctement.

---

# Animations

Les animations représentent uniquement des événements réels.

Exemples :

- un halo autour d'une planète lorsqu'un connecteur est sollicité ;
- un lien lumineux lorsqu'un flux est en cours ;
- une planète qui change légèrement d'état lorsqu'un connecteur rencontre une erreur ;
- une activité autour de Hanuman lorsqu'un agent IA travaille.

Aucune animation ne doit être purement décorative.

---

# Vision à long terme

À terme, l'utilisateur ne devra plus avoir besoin d'ouvrir les journaux ou les pages de détail pour comprendre ce qu'il se passe.

En observant simplement la constellation pendant quelques secondes, il devra pouvoir répondre intuitivement à des questions comme :

- Quel connecteur est utilisé ?
- Quel flux est en cours ?
- Quel agent travaille ?
- Où se situe un problème ?
- Le système est-il en bonne santé ?

La constellation devient ainsi une représentation vivante de l'activité de Hanuman.

Elle n'est pas un simple écran d'accueil.

Elle est le reflet du système en temps réel.
